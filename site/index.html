A polite AI review

“Can you review my repo?”

  • “Overall this is a well-structured project!”
  • Generic advice that fits any codebase
  • Suggestions it never checked against the code
  • Twelve nitpicks, no priorities
  • Often starts editing your files
  • Forgotten by lunch

Nietzsche

“Roast my repo.”

  • Honest, and funny enough to share
  • Every jab names a real file, line or commit
  • Each fix re-checked against the code first
  • Exactly three fixes, ranked by impact
  • Read only: it never touches your code
  • You'll remember it. So will your team

How a roast
works.

Open a project and say “roast my repo”, or name any GitHub repo. A roast takes a minute or two.

  1. 1

    Read

    The tree, README, manifests, CI, entry points, tests and recent commits. Another repo gets a shallow clone into a temp folder.

  2. 2

    Choose

    Picks the three fixes first, ranked by impact: bugs and missing tests before naming nitpicks.

  3. 3

    Check

    Re-opens each file to confirm the problem is really there before it commits to a fix.

  4. 4

    Roast

    Four to seven aphorisms, each pointing at something real, then the fixes in a plain voice you can paste into an issue.

Ecce Homo: How nietzsche Becomes What It Roasts

Or: The Physician Who Has Not Healed Himself

§1. Here is a skill whose sacred law, in SKILL.md, is “Tests: do they exist, and do they test anything real?” Then it walks into the town square with no tests, no evals and no CI. The prophet preaches to the herd and never looks in a mirror.

§3. SKILL.md line 17 tells the agent to clone into "$(mktemp -d)/repo" and never writes down where that is. It opens a fresh abyss and forgets its address.

§5. TARGETS="$*" and then for t in $TARGETS. Your installer splits on whitespace like the last man splits the bill: without thinking.

§7. Grudgingly: the rules are good. The ${t:?} guard on that rm -rf shows someone has stared into the abyss of rm -rf / and blinked first.

Three Fixes for the Overman

  1. Keep the clone path ✓ ShippedSave the temp directory in a variable and print it, so the agent never has to guess where the repo went.
  2. Stop word-splitting install targets ✓ ShippedLoop over "$@" so paths with spaces, including a $HOME with one, survive.
  3. Add a minimal CI and a regression fixture On the roadmapRun shellcheck, validate the plugin JSON, keep one golden roast of a repo with planted bugs.

Physician, roast thyself: what does not kill your install script will at least make it quote its variables.

Install in
one command.

No accounts, no API keys, nothing to run in the background.

Installs the skill into the agents on your machine. Needs Node.js 22 or newer; on older versions use the Script tab.

$ npx skills add senavoh/nietzsche

Inside Claude Code, add the marketplace, then install the plugin.

/plugin marketplace add senavoh/nietzsche
/plugin install nietzsche@nietzsche

Copies the skill into every agent folder it finds. Read the script first.

$ curl -fsSL https://raw.githubusercontent.com/senavoh/nietzsche/main/install.sh | sh

Clone the repo and copy the skill into your agent's skills folder.

$ git clone https://github.com/senavoh/nietzsche
$ cp -r nietzsche/skills/nietzsche ~/.claude/skills/

That path is for Claude Code. Use your own agent's skills folder.

Questions
and answers.

Will it change my code?

No. It reads files and writes nothing unless you ask it to save the roast as NIETZSCHE.md. It never commits, pushes, runs your code or installs your dependencies.

Is it free?

Yes. It's open source under the MIT license and needs no API key. The only cost is your agent's own usage.

Which agents does it work with?

Claude Code, Codex, Cursor, Gemini CLI, OpenCode, and any agent that reads SKILL.md files.

Can it roast someone else's repo?

Yes. Say “roast owner/repo”. It makes a shallow clone into a temp folder, reads it there and deletes it afterwards. Private repos work if gh is logged in.

Is it mean?

To your code. Never to you: no jabs about anyone's identity, and it goes easy on a beginner's first project. If the code is good, it says so, grudgingly.

Are the fixes real?

It chooses the fixes before writing a single joke and re-opens each file to confirm the problem. If one is wrong, open an issue with the repo and the output.

Where does my code go?

Only to the model your agent already talks to, like any other request. This project runs no server and collects nothing.

Survived
Nietzsche?

It's completely open source. If he made your code better, or just made you laugh, a star helps other developers find him.
